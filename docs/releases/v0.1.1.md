# 0.1.1

本版本在 0.1.0 基础上修正品牌素材、完善安装和服务依赖说明，并补齐发布版本核对流程。插件由 shell 社区维护，不代表 Halo 官方；ImgNest 是同一作者维护的独立自托管图床，其适配是可选功能。使用通用 CDN URL 规则无需部署 ImgNest。

## 变化

- 将脚手架遗留的 Halo 官方图标替换为插件自有图标。安装包与应用市场使用仓库内同一份 `src/main/resources/logo.png`。
- 补充图片查询、浏览器 CDN 请求、ImgNest 上传与删除的数据去向，以及 Token 保存方式、外部服务成本和停用影响。
- 明确 ImgNest 按 `/api/variants` 和 `/api/v2` 接口契约适配；现有开发记录未固定 ImgNest 提交，不虚构最低兼容发布版本。
- 发布流程使用对应版本说明，校验源码版本、jar 文件名和包内 `plugin.yaml` 版本，并附带 SHA-256；拒绝覆盖已有 Release。

本版本未更改图片处理业务逻辑和配置结构。

## 安装与升级

1. 使用 Halo 2.20 及以上；插件字节码目标为 Java 21，运行环境还需满足所用 Halo 版本的 Java 要求。先备份 Halo 数据、插件设置、ImgNest 存储策略配置；保留原有 0.1.0 安装包。
2. 从本版本 Release 下载 `halo-plugin-responsive-images-0.1.1.jar`，核对随包提供的 SHA-256；市场版本填写 `0.1.1`，与 jar 内 `plugin.yaml` 的版本保持一致。
3. 在 Halo 后台通过插件管理安装或更新 jar，启用后核对图标、版本、图片来源及存储策略。通用 CDN 配置不需要 ImgNest；使用 ImgNest 时需自行部署实例并按 README 确认接口和权限。
4. 在自己的主题下检查正文和封面图片、桌面与手机视口、懒加载、服务超时回退；使用 ImgNest 存储策略的站点还需检查上传、缩略图与回收站删除。

## 配置迁移

插件标识仍为 `responsive-images`；插件设置和 ConfigMap 名称、ImgNest 存储策略模板 `responsive-images-imgnest`、已有附件注解格式均不变，无需主动迁移或重建附件。不要为了更新图标而删除插件、存储策略或已有附件。

Token 保存在 Halo 存储策略的 ConfigMap 配置中，本插件没有额外实现静态加密；请保护数据库和备份。正文渲染查询会发送完整图片 URL，ImgNest 上传会发送图片内容及文件携带的元数据。费用、数据保留和备份由所用图床、存储及 CDN 实例的运营者负责，详见 README。

## 回退与停用

1. 回退前重新备份当前 Halo 数据和配置。禁用插件，通过 Halo 插件管理更新为保留的 `halo-plugin-responsive-images-0.1.0.jar`，再启用并核对原有设置。
2. 如果 Halo 拒绝降级，先在备份环境验证恢复原有备份的方案；不要直接卸载或删除附件来强制降级。
3. 回退后检查已有图片链接及查询；使用 ImgNest 策略时检查上传、缩略图和删除。回退插件不会恢复已被删除或回收的远程图片。

仅关闭正文/模板处理开关不会关闭 ImgNest 存储策略。禁用插件会停止图片重写及 ImgNest 存储处理；远程图片不会因此自动删除。卸载前应先迁移后续上传策略并备份配置；Halo 对策略、配置和附件记录的保留行为需在备份环境确认。删除附件则可能触发 ImgNest 同步回收，不能当作卸载步骤。

已有 AI 辅助开发记录覆盖 Halo 2.20.20、2.22.11、2.27.0，以及真实 ImgNest 查询、上传、缩略图、删除、坏 Token 和查询服务不可用等路径。记录见仓库 PR #1、#2、#3；这些历史记录不等同于维护者对 0.1.1 的人工复核。待发布版本的人工结果、Halo/ImgNest 精确版本和安装包摘要应登记在 `docs/release-checklist.md`，未确认的项目保持待确认，不作完成声明。
